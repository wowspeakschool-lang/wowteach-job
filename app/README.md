# app — новая платформа (React + Vite + TypeScript)

Каркас новой версии. **Боевая платформа продолжает работать из корня
репозитория** — файлы `index.html`, `hr.html`, `apply*.html`, `soglasie.html`
раздаёт GitHub Pages на `job.wowteach.ru`. Этот каталог изолирован: свой
`package.json`, свой Vite root, своя сборка в `app/dist`. Собрать отсюда
что-то поверх боевых файлов физически нельзя.

Эталон для переноса — снимок в `../legacy/`.

## Команды

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm run typecheck
npm run lint
npm run build      # typecheck + сборка в app/dist
```

## Три точки входа, а не одно SPA

| Файл | Приложение | Боевой адрес |
|------|-----------|--------------|
| `index.html` | Кабинет кандидата | `job.wowteach.ru/` |
| `hr.html` | HR-панель | `job.wowteach.ru/hr.html` |
| `apply.html` | Анкеты | `job.wowteach.ru/apply.html` |

Так сделано не ради красоты:

- у панели и кабинета **разное хранилище сессии** — cookie на `.wowteach.ru`
  против localStorage. Свести их в один бандл нельзя, иначе вход кандидата
  начнёт перетирать сессии персонала на соседних поддоменах платформы;
- анкеты открывает аноним — ему незачем грузить код панели;
- имена файлов совпадают с боевыми адресами, поэтому переключать приложения
  на новую версию можно **по одному**, а не всё разом.

## Что уже перенесено (Phase 0)

| Модуль | Что это |
|--------|---------|
| `services/supabase/hosts.ts` | цепочка из трёх хостов, ключ, таймаут |
| `services/supabase/failoverFetch.ts` | переключение на запасной хост; повтор **только** для чтения и авторизации |
| `services/supabase/cookieStorage.ts` | общая cookie-сессия персонала + префикс для staging |
| `services/supabase/client{Hr,Cabinet,Public}.ts` | три клиента с разным хранением сессии |
| `utils/msk.ts` | московское время: показ через `Intl`, сборка через литеральный `+03:00` |
| `utils/date.ts` | форматы дат — раздельно для панели и кабинета, они разные |
| `utils/html.ts` | `esc()` для мест, где осознанно вставляем сырой HTML из базы |
| `constants/policy.ts` | значения, продублированные на сервере: `CANCEL_HOURS`, лимиты файлов, шаги |

Экранов нет — они появятся после того, как будет зафиксирована дизайн-система.

## Правила переноса

1. **Заморожено:** RPC и их аргументы, таблицы и поля, роли и права, тексты
   писем, расчёты (скоринг, баллы чек-листа, сроки, таймзоны), правила
   переходов статусов, что и когда пишется в базу.
2. **Свободно:** раскладка, навигация, фильтры, поиск, сортировка, состояния
   загрузки/пустоты/ошибки, диалоги вместо `alert`, сохранение состояния,
   мобильная вёрстка, доступность.
3. **Проверка:** уборка не должна менять ни одного запроса к базе. Нужен новый
   RPC — значит это уже фича, её отдельной задачей.
4. **Порядок внутри экрана:** сначала переносим как есть и сверяем с продом,
   потом отдельным коммитом накатываем уборку. Тогда видно, на каком из двух
   шагов что-то отвалилось.

## Типы базы данных

Генерируются Supabase CLI прямо в файл (в проекте ~150 таблиц всей платформы,
через чат это тащить бессмысленно):

```bash
npx supabase gen types typescript --project-id vtcxghsqymwkyiogpndf \
  > src/types/database.generated.ts
```

Сейчас там заглушка. Отдельно понадобится ручной тип для `hr_applications.answers`:
это `jsonb` с **тремя разными схемами** — преподаватель, менеджер ВУ, продажи.
Сейчас схема нигде не описана и угадывается по ключам; опечатка в ключе тихо
затирает ответ кандидата. Это то место, где TypeScript окупается сразу.

## Окружения

См. `.env.example`. Секретов там нет и быть не может: всё, что попадает в бандл
Vite, публично — ровно как сейчас в боевых html. Ограничения доступа живут
в RLS и в `SECURITY DEFINER`-функциях.

⚠️ `VITE_AUTH_STORAGE_PREFIX` в проде должен быть **пустым**, иначе персонал
разлогинится. На staging его задают (например `beta-`), чтобы бета на том же
домене `.wowteach.ru` не перетирала боевую сессию.

Перед подъёмом staging-поддомена не забыть три вещи, иначе вход не заработает:
добавить домен в Cloudflare Turnstile, в CORS прокси `api.wowteach.ru`
и `api2.wowteach.ru`, и в Supabase Auth → Redirect URLs.
